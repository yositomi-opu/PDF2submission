# Moodle 5.2検証結果

実施日: 2026-10-13

## 結論

PDF2submission 1.0.0を新規のMoodle 5.2.4にインストールし、QR用紙生成、300dpiでの実PDF読取・分割、教員権限による代理提出まで成功した。
プラグインの修正は行っていない。これはMoodle本体・DB・PDF外部ツールを使ったCLI統合検証であり、ブラウザ操作の検証ではない。

## 検証環境

- Moodle 5.2.4 (Build: 20261005)、内部版2026042004
- PHP 8.3.35、PostgreSQL 16.15
- PDF2submission 1.0.0、コンポーネント `block_pdf2submissionbeta`、内部版2026101302
- 公式配布 `moodle-5.2.4.tgz` のSHA256: `8569b63f1e97416ecb67ec75767dd20675892c7a62a5e90d1647366fddf873cf`
- 検証したプラグインZIPのSHA256: `0058acd476d71631964b12fd26339abc50c8b5600d00c71948e67baab3d2aebf`
- インストール先の全プラグインファイルがリリースZIPと一致することを確認。
- 専用Composeプロジェクト `pdf2-m52-validation`、新規DB、一時moodledata、内部ネットワークで分離。メール送信を無効化。
- 既存Moodle、MacMoodleSetupのソース・同梱コピー、既存DB・答案は不使用。全コース・教員・学生は架空。

## 実施内容と結果

1. Moodle本体を新規インストール後、正式版ZIPを `public/blocks/pdf2submissionbeta` に展開してCLIアップグレードを実行。登録成功、署名キー生成、表示名を確認。
2. `scripts/tests/pdf2_integration.php` を検証コンテナ内で `MACMOODLE_PDF2_TEST=1` を指定して実行。結果は `INTEGRATION SUCCESS`。
   - 学生2名のQR用紙生成、Ghostscriptによる300dpi画像化、ZBar読取、学生別PDF分割。
   - 署名検証、別課題QRの拒否、QRのない先頭ページのエラーと登録禁止。
   - 代理提出後の `submitted` 状態と、学生あたり1個のMoodle保存PDFを確認。
   - 重複確定拒否、既存提出の保護、明示した上書き、ファイル名、空の提出レコードへの再登録。
   - 学生による取込アクセス拒否、プライバシー対象コンテキストの検出。
3. 同じ架空コース内に2課題を作成し、学生2名・教員の保存順序を設定。実際の用紙生成結果から8ページの混合PDFを作成し、画面の取込処理でも使う `batch::analyse` を実行。
   - 第1課題: 学生1が1–2ページ、教員用紙と続きが3–4ページ、学生2が5ページ。
   - 第2課題: 学生1が6–7ページ、学生2が8ページ。
   - 教員の3–4ページを除外し、残りを課題・学生ごとに正しく振り分け。
   - 第1課題を提出した時点では第2課題は未確定。続いて第2課題を個別に確定。
   - 4件すべてで `submitted`、非空PDF、Moodleファイル1個を確認。結果は `MULTI-ASSIGNMENT INTEGRATION SUCCESS`。
4. 検証終了時に提出済みレコード6件（基本テスト2件＋複数課題4件）を確認。検証用コンテナとネットワークを削除し、一時DB・moodledataを破棄。既存の2コンテナは稼働を維持。

ログに出た「Not sending email」は、検証環境のメール送信禁止設定による予定どおりの通知であり、提出の失敗ではない。

## 確認範囲の限界

- ブラウザのログイン・ファイル選択・確認画面の操作は未検証。外部接続可能なネットワークへの変更は自動承認レビューで拒否されたため、内部ネットワークを維持してCLI検証を完了した。
- 新規インストールを確認したもので、既存4.5サイト自体の5.2へのアップグレード試験ではない。
- 実紙の再スキャンではなく、生成PDFを実際の300dpi読取処理に通した。0.2.03での印刷・実スキャン成功は利用者の別途報告。
- 90名規模の負荷、PHP 8.4、他DB、Moodle 5.2の全パッチ版を網羅したものではない。
