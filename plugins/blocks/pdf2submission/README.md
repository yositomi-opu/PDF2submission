# PDF2submission for Moodle 4.5

QRコード付きの記入用紙を生成し、スキャンPDFを学生別に分割してMoodleの課題へ代理提出します。
Moodle 4.5 / PHP 8.3向けに作成したベータ版です。学生自身がPDFをアップロードする操作は不要です。

元の着想・ワークフローは喜多敏博氏の [pdf2submission](https://github.com/kita-toshihiro/pdf2submission)
です。この版は現行Moodle APIで実装し直しており、元の古いFPDIは同梱していません。
旧版の作者がこの改修版を検証・承認したものではありません。コードはGPL-3.0-or-laterです。

## 導入

MacMoodleSetupではDockerイメージに同梱されます。リポジトリ更新後 `make setup start` を実行します。
既存環境は更新前に `make backup` してください。Moodleの管理者でログインします。

他のMoodleへ手動導入する場合は、このフォルダを `blocks/pdf2submission` に置き、
管理画面の通知またはMoodle CLIのupgradeを実行します。Linux上のPHP 8.3に加え、
`/usr/bin/python3` とpypdf、`/usr/bin/gs`、`/usr/bin/zbarimg`、`/usr/bin/timeout` が必要です。
Moodle 5系・他OSは未検証です。

## 使い方

1. コースに学生を登録し、ファイル提出を有効にした個人用の「課題」を作成します。
   PDFを許可し、提出可能期間を設定してください。
2. コースの編集モードをオンにし、ブロックを追加 →「PDF2submission」を選びます。
   日本語・英語ともブロック名は「PDF2submission」です。
3. ブロックの「課題」ドロップダウンで課題名を選択します。用紙生成・取込画面でも課題を切り替えられます。
4. 「学生別QR用紙をダウンロード」で、受講者ごとにQRと氏名が印字されたA4用紙を取得・印刷します。
   ページは学籍番号（idnumber）の自然順（例: A2 → A10）です。未設定は最後にまとめ、同じ番号の場合はユーザー名、内部ID順です。
   最後に、用紙を生成したログイン中の教員用QRページを1枚追加します。教員用の氏名・IDナンバーと「教員用」を表示します。
   QRは25 mm角の枠内に配置し、右側にコース名・課題名・氏名を左揃えで表示します。
   記入案内や罫線はなく、下部は空白です。既存ワークシートとのPDF合成に利用できます。
5. 回収した用紙をスキャンして、1回100 MB以内のPDFにします。
6. 「スキャンPDFのアップロード」でPDFを選択して「QRコードを読み取って確認」。各学生のページ番号とPDF内容を確認します。
7. 「確認済み・提出物として登録」で課題への代理提出を確定します。

点3つのメニューはMoodleのブロック設定用です。用紙生成・アップロードには使いません。
WebDAVのマウントは不要です。PDFはブラウザから直接アップロードし、確認後に登録します。

管理者はそのまま使えます。一般の教員はこのブロックの管理権限、課題の採点権限に加えて
`mod/assign:editothersubmission`（他の学生の提出を編集する）が必要です。
管理者が必要なコース・担当者に限定して許可してください。本プラグインが全教員へ自動付与することはありません。

## 対応範囲と注意点

- 新版で生成した署名付きQRを使用します。別サイト・別課題・旧版のQRは拒否します。
- 大学Moodleの旧用紙には、そのサイト内の課題ID・学生IDが入っています。Mac側と一致しないため、
  読み出せても自動対応させません。旧用紙の救済には名簿等で対応を確認する別機能が必要です（未実装）。
- 各学生の先頭ページにQRが必要です。QRを読み取れないページは直前の学生の続きとして、元のページ順で連結します。
  確認画面で自動連結したページ番号を表示します。別の学生のQR読取失敗も直前の学生へ連結されるので内容を確認してください。
  最初のQRより前のページ、複数QR、無効なQRはエラーにします。無効なQRの後は次の有効なQRまで引き継ぎません。
  エラーが1ページでもある場合、全体を確定できません。
- 教員用QRページと、その後に続くQRなしページは取込対象から除外し、確認画面にページ番号を表示します。
  次の学生用QRから学生分の取込を再開します。教員用QRも署名と課題を検証し、無効・別課題のQRはエラーです。
- 空の提出レコードには再登録できます。既存ファイルがある場合は確認画面の「既存の提出PDFを上書きする」で置換できます（既定はオフ）。
  今回のPDFに含まれる学生のみ対象です。既存の採点・フィードバックは再確認してください。
  登録直前に受講・権限・提出可否・PDFサイズ・形式を再確認します。
- グループ提出、匿名用紙、既存PDFを背景にした用紙作成、フォルダ自動監視には未対応です。
- 登録前に必ず内容を確認してください。QR読取用に各ページを300 dpiのグレースケール画像へ変換します。
  読取後に提出するPDFは元のページを使用します。実スキャンPDFで読取を検証していますが、
  紙の汚れ・傾き・QRの破損などによって読み取れない場合があります。

## データとプライバシー

確認用データはMoodleのtempディレクトリに教員別・ランダムな識別子で保存します。
ブラウザからのアクセスは当該教員と権限のある課題に限定します。
有効期限は24時間で、期限後の定期クリーンアップで削除します（cronが必要、通常25時間以内）。
確定した提出物はMoodle標準の課題・ファイルAPIで保存し、Moodle標準の提出イベントも発生します。
外部のAI・クラウド処理サービスへ答案を送信しません。
プライバシーAPIは確認用PDFのエクスポートと削除に対応します。削除対象の学生を含む一時バッチは
全体を削除するため、教員は必要なら元のPDFから再度取り込んでください。

MoodleのDBを別環境へ完全に復元すれば署名キーも引き継がれます。キーを失うと既存の新版用紙は検証できなくなります。

## PDF処理の制限とエラー

1回80〜90名程度（1人2ページなら約180ページ）を運用の目安とします。人数・ページ数の固定上限はありません。
アップロード上限は100 MiB（画面表記100 MB）で、フォームと処理開始時に確認します。
200名規模では学生の区切りで2〜3ファイルに分割してください。各ファイルの先頭には学生の有効なQRが必要です。
処理時間は読取・PDF結合それぞれ最大900秒（15分）、解析リクエストのPHP時間枠は1860秒です。
読取PythonのCPU時間枠も900秒に拡大し、1ページの画像化15秒・QR読取10秒、メモリ1 GiBは維持します。
人数だけで完了を保証するものではなく、ページ数・画質・サーバー性能によっては分割が必要です。

PHP・Moodle・Webサーバー側の制限も別途適用されます。Moodleの512 MB設定だけでは他の制限は変わりません。
100 MiBを扱う場合、PHPのupload_max_filesizeは100M以上、post_max_sizeとnginxのclient_max_body_sizeは
送信時の付加情報も考慮して128M以上を目安にします。解析の時間枠を全て使う場合は、PHP-FPMの
request_terminate_timeout、nginxのfastcgi_read_timeout／proxy_read_timeoutなど、経路上の該当する上限を
1920秒以上に調整してください。これらのサーバー設定はプラグインの更新では変更されません。
課題に登録する学生別PDFには、その課題の提出ファイル容量上限が別途適用されます。
エラー画面には暗号化、必要ツールの不足、失敗ページ、時間切れなどの理由を表示します。
管理者向けの詳細はMoodleデータディレクトリの `temp/pdf2submission/<教員ID>/<取込ID>/processor.log`
に保存します。一時データとともに期限後に削除されます。

## 登録時の動作とファイル名

登録中はログインセッションのロックを解放し、同じブラウザの別タブでMoodleを利用できます。
登録完了後は確認結果へ移動し、完了人数を表示します。PHPの実行時間制限は登録中のみ解除しますが、
Webサーバーやプロキシのタイムアウトは別途適用されます。登録速度そのものの改善を保証するものではありません。
新規提出PDFと確認用ダウンロードの名前は `課題名_識別番号.pdf` です。
識別番号はプロフィールのIDナンバー（idnumber）、未設定ならユーザー名（username）、
それもない場合はMoodle内部の数値IDを使います。既存の提出ファイルは変更しません。
