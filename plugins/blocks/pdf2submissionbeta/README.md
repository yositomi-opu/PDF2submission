# PDF2submission Beta 0.2.03

Moodle 4.5 / PHP 8.3向けの独立したベータ版ブロックです。
現行の `block_pdf2submission` は変更・置換しません。表示名は **PDF2submission Beta**、
インストール先は `blocks/pdf2submissionbeta` です。単独でも導入できます。
大学の旧PDF2submissionとは別実装です。元の着想は喜多敏博氏の
[pdf2submission](https://github.com/kita-toshihiro/pdf2submission) です。GPL-3.0-or-later。

## 導入

ZIPをMoodleの「プラグインをインストールする」で追加するか、フォルダを
`blocks/pdf2submissionbeta` に置いて管理画面の通知でインストールします。
コースのブロック追加で **PDF2submission Beta** を選びます。
現行版のフォルダ・データ・ブロックは残してください。

Ghostscript、ZBar、Python pypdf、GNU timeoutが必要です（Linuxの/usr/bin下）。
Moodle 5系は未検証です。まず検証用課題で生成・取込・登録を確認してください。
管理者、またはこのブロックの管理権限と課題の採点・代理提出権限
`mod/assign:grade` / `mod/assign:editothersubmission` のある教員のみ利用できます。
個人のファイル提出形式の課題が対象です。グループ提出は未対応です。

## QR用紙の順序を保存する

ブロック内の「保存済みの順序」を開き、UTF-8 CSVを選んで「順序を保存」を押します。
1列に学籍番号を希望の順序で書きます。先頭行は `idnumber`、`学籍番号`、`学生番号`
のいずれかにするか、省略できます。ユーザー名で指定する場合は `username` が必須です。

```csv
idnumber
00123
00101
00118
```

- Excelで編集するときも先頭のゼロを保持してください。UTF-8 BOM付き・CRLF改行も読めます。
- 教員を含む、そのコースの有効な登録参加者全員（ロールによる制限なし）と照合し、内部ユーザーIDとしてコース共通で保存します。
  元CSVは独自保存しません。Moodle標準のファイルピッカーの一時ファイルは通常の清掃対象です。
- 不明・重複・複数の参加者に一致する番号があれば保存せず、既存の順序を維持します。
- CSV未指定の学生は末尾に学籍番号の自然順で追加します。有効な登録がなくなった人は印刷しません。CSVに指定した提出権限のない参加者は教員用（取込除外）のQRとして印刷します。
- 「学籍番号順に戻す」で指定順序を解除します。学生がプロフィールの番号を変えても保存済みの内部ID順は維持されます。
- ブロックの課題を選ぶと、その場でQR用紙をダウンロードします。教員はCSVに記載した位置で印刷し、未記載なら自動追加しません。
  学生ロールを兼ねる教員（採点権限あり）や用紙生成者も同様で、重複印刷しません。
  順序CSVへの登録だけでは課題の提出権限は付与しません。

QRは30 mm角の枠内に、用紙の上端から5 mm・左端から12 mmの位置に配置します。
右側にコース名・課題名・氏名を左揃えで表示します。文字上端はQR枠の上端から約8 pt下、文字サイズ11 pt・行送り19 pt（行間8 pt）です。

## 複数課題のスキャンを取り込む

1. 同じコースの答案をまとめたPDFをブロック内で選びます。各学生・各課題の先頭ページに、その課題のQRが必要です。
2. 「返却結果を確認する」で300dpi読取を実行し、確認ページへ移動します。まだ提出物は登録しません。
3. 右側の課題一覧で対象を切り替え、学生名・元PDFのページ番号・学生別PDFを確認します。
   狭い画面では課題一覧を上部に表示します。
4. 各課題の「確認済み・提出物として登録」を押します。登録済みの課題にはチェックが付きます。
   他の課題は未登録のままです。一括で全課題を確定する動作はありません。

QRは署名・課題・学生を検証します。別コースは分割してアップロードしてください。
読取不能・無効・複数QRのエラーがあれば、その取込全体の登録を止めます。
QRなしページは直前の課題・学生の続きにします。新しい学生のQRが読み取れなかった場合も
同じ挙動になるため、自動連結ページとPDF内容を必ず確認してください。
教員用QRとその直後のQRなしページは除外します。

現行のPDF2submission 0.1系で同じMoodleが発行した署名付きQRも読めます。
**逆方向（ベータ版QRを現行版で読む）は対応しません。**
大学の別システムで発行した古いQRや別サイトのQRは対応しません。
現行版の署名キーが失われた場合は、その用紙のベータ版での検証もできません。

登録はMoodle標準の代理提出APIです。学生別ファイル名は課題名と学籍番号を使用します。
既存提出は既定では置換せず、課題ごとに「上書き」を指定できます。課題の期間・ロック・容量制限も適用されます。
同じ課題に対する現行版とベータ版の登録は共通ロックで直列化します。

## 上限とデータ

1回100 MiB、読取・結合それぞれ最大15分、PHP解析枠31分です。
80〜90名程度を目安とし、200名規模は学生の区切りで2〜3分割してください。
ページ数・人数の固定制限ではなく、画質・枚数・サーバー性能に依存します。
PHP・Moodle・リバースプロキシの容量・時間制限は別途設定が必要です。
1ページの画像化15秒・QR解析10秒、読取プロセスのメモリ1 GiBです。

一時PDF・振り分け情報はアップロードした教員専用で、24時間後に削除対象になります（cronが必要）。
保存順序はコースごとに残ります。コース削除時にも削除します。
プライバシーAPIは保存順序と一時PDFに対応し、該当ユーザーの削除要求時は関係する順序設定・取込バッチ全体を削除します。
学生・課題・認証情報を外部に送信しません。
